# 프로젝트 개요

MAC(Multiply-Accumulate) 연산으로 패턴을 판별하는 Mini NPU 시뮬레이터

# 실행 방법

`python3 main.py`

- 모드 1 : 3×3 필터 A, B와 패턴을 3줄씩 공백으로 구분해 입력
- 모드 2 : `data.json` 일괄 판정

모드 2에서 사용하는 `data.json`은 `main.py`와 같은 위치에 두어야 합니다.

# 실행 환경

- Ubuntu 26.04 LTS
- Python 3.14.4

# 기능 목록

- 3×3 필터와 패턴 입력해 판정하기
- `data.json` 케이스 일괄 판정하기
- 판정 결과와 정답(expected) 비교하기
- 크기별 MAC 연산 시간 확인하기
- 테스트 총계와 실패 사유 확인하기

# 파일 구조

```
├── main.py
```

# data.json 스키마

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `filters.size_{N}.cross` | `number[N][N]` | 십자가 필터 |
| `filters.size_{N}.x` | `number[N][N]` | X 필터 |
| `patterns.size_{N}_{idx}.input` | `number[N][N]` | 판정할 패턴 |
| `patterns.size_{N}_{idx}.expected` | `string` | 정답 라벨 (`+` 또는 `x`) |

패턴 키에서 N을 추출해 같은 크기의 `size_{N}` 필터와 짝지어 판정합니다.

# 구현 요약

| 항목 | 내용 |
| --- | --- |
| 데이터 구조 | `Grid` 클래스. `get(r, c)` / `set(r, c, value)`로 칸 단위 접근 |
| MAC 연산 | 이중 반복문으로 같은 자리 값을 곱해 누적. 곱셈 N²번, 덧셈 N²번 |
| 라벨 정규화 | `normalize_label()`이 `{"+": Cross, "cross": Cross, "x": X}` 표로 변환 |
| 동점 처리 | `abs(a - b) < 1e-9`이면 UNDECIDED(모드 1은 `판정 불가`) |
| 성능 측정 | `time.perf_counter()`로 MAC 호출 구간만 10회 반복 평균 |
| 예외 처리 | 키 형식·크기 불일치, 숫자 아닌 값, 필터 누락은 케이스 단위 FAIL |

## FAIL 원인

```
--- size_5_1 ---
Cross 점수: 0.9
X 점수: 0.8999999999999999
판정: UNDECIDED | expected: X | FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)
--- size_13_2 ---
Cross 점수: 7.499999999999997
X 점수: 7.5
판정: UNDECIDED | expected: Cross | FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)
--- size_25_1 ---
Cross 점수: 4.9
X 점수: 4.899999999999999
판정: UNDECIDED | expected: X | FAIL (동점(UNDECIDED) 처리 규칙에 따라 FAIL)
```

세 케이스 모두 Cross 점수와 X 점수의 차이가 EPSILON(`1e-9`)보다 작습니다.

| 케이스 | Cross 점수 | X 점수 | 차이 |
| --- | --- | --- | --- |
| size_5_1 | 0.9 | 0.8999999999999999 | 약 1.1e-16 |
| size_13_2 | 7.499999999999997 | 7.5 | 약 2.7e-15 |
| size_25_1 | 4.9 | 4.899999999999999 | 약 1.8e-15 |

이 정도 차이는 MAC 누적 과정에서 생긴 부동소수점 오차이며 실제 점수 차이로 볼 수 없습니다.
따라서 `abs(a - b) < 1e-9` 규칙에 따라 어느 쪽이 더 큰지 판별할 수 없다고 보고 UNDECIDED로 처리하며, expected와 일치하지 않아 FAIL이 됩니다.
